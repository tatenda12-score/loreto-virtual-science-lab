================================================================================
1. PROJECT OVERVIEW
================================================================================

Name:           Virtual Science Laboratory System
Purpose:        A full-stack web application that allows students at Loreto High
                School to run virtual science experiments (Physics, Chemistry,
                Biology), submit lab reports with observations, and receive
                auto-graded scores. Teachers can review submissions, provide
                written feedback, and override scores.

Target Users:
  - Students    → Run experiments, submit observations, view scores
  - Teachers    → Create experiments, view all submissions, grade/feedback
  - Admins      → Full system access (teacher capabilities + delete experiments)


================================================================================
2. TECHNOLOGY STACK
================================================================================

--- BACKEND ---
  Language:         Python 3.12+
  Framework:        FastAPI
  Server:           Uvicorn (dev), Gunicorn + Uvicorn workers (prod)
  Database:         SQLite (dev — loreto_lab.db), PostgreSQL-ready
  ORM:              SQLAlchemy 2.0 (Mapped columns, DeclarativeBase)
  Migrations:       Alembic
  Auth:             JWT (python-jose, HS256 algorithm)
  Password Hashing: passlib + bcrypt (v4.0.1)
  Validation:       Pydantic v2 + pydantic-settings
  Env Management:   python-dotenv (.env file)
  API Versioning:   /api/v1/ prefix

--- FRONTEND ---
  Language:         TypeScript
  Framework:        React 19 (with Vite 8 as build tool)
  Routing:          react-router-dom v7
  HTTP Client:      Axios (with interceptors for JWT + 401 handling)
  Styling:          TailwindCSS v4 (@tailwindcss/vite plugin)
  UI Components:    Radix UI (react-slot), class-variance-authority, clsx,
                    tailwind-merge, lucide-react icons
  Linting:          oxlint
  Path Aliases:     @ → src/ (configured in vite.config.ts + tsconfig)

--- DEV TOOLING ---
  Version Control:  Git (.gitignore configured)
  Proxy:            Vite dev server proxies /api → http://localhost:8000
  Ports:            Backend: 8000, Frontend: 5173

4. WHAT HAS BEEN BUILT (COMPLETED FEATURES)
================================================================================

--- BACKEND (100% functional) ---

  [x] FastAPI application with lifespan hooks and structured logging
  [x] CORS middleware (localhost:3000, localhost:5173 allowed)
  [x] TrustedHost middleware for production
  [x] Global exception handler (catch-all → 500 JSON response)
  [x] Health check endpoints: GET /health, GET /health/db

  [x] SQLAlchemy 2.0 ORM models:
      - User (id, full_name, email, hashed_password, role, is_active,
              is_verified, class_level, subject_code, gender, timestamps)
      - Experiment (id, title, subject, difficulty, description,
                    instructions (JSON), parameters (JSON), created_by, timestamps)
      - Submission (id, student_id, experiment_id, recorded_observations (JSON),
                    calculated_score, teacher_feedback, status, timestamps)

  [x] Role-based access control (RBAC):
      - UserRole enum: admin, teacher, student
      - require_roles() dependency factory for endpoint-level permission checks
      - OAuth2PasswordBearer token flow

  [x] Authentication system:
      - POST /api/v1/auth/register  → create account (defaults to student role)
      - POST /api/v1/auth/login     → OAuth2 password flow → JWT access token
      - GET  /api/v1/auth/me        → authenticated user profile
      - bcrypt password hashing with constant-time verification
      - JWT tokens with configurable expiry (default 30 min)

  [x] Experiments CRUD:
      - POST   /api/v1/experiments/        → create (teacher/admin only)
      - GET    /api/v1/experiments/        → list all (any auth user, paginated)
      - GET    /api/v1/experiments/{id}    → single experiment
      - PATCH  /api/v1/experiments/{id}    → update (teacher/admin)
      - DELETE /api/v1/experiments/{id}    → hard delete (admin only)

  [x] Submissions system:
      - POST  /api/v1/submissions/                 → student submits observations
      - GET   /api/v1/submissions/me               → student's own submissions
      - GET   /api/v1/submissions/{id}             → single submission (owner or teacher)
      - GET   /api/v1/submissions/experiment/{id}  → all subs for experiment (teacher/admin)
      - PATCH /api/v1/submissions/{id}/grade       → teacher grades (feedback + score override)

  [x] Science Engine (services/science_engine.py):
      - calculate_ohms_law(voltage, resistance) → current, power
      - calculate_velocity(distance, time) → velocity
      - calculate_titration(vol_acid, molarity_acid, vol_base) → molarity_base, moles
      - calculate_ph(H+ concentration) → pH
      - evaluate_submission() → score single measurement (linear decay model)
      - grade_submission() → average score across all graded fields

  [x] Auto-grading on submission:
      - When student submits, the engine compares observations against
        experiment.parameters.expected_values using tolerance-based scoring
      - Score is stored in submission.calculated_score automatically

  [x] Database seeder (scripts/seed.py):
      - Idempotent seed script
      - Creates: 1 admin, 1 teacher, 3 students
      - Creates: Ohm's Law experiment + Acid-Base Titration experiment
      - Creates: 3 sample submissions with realistic noisy data
      - All seed users share password: Demo123!

  [x] Alembic migration infrastructure configured

6. HOW TO RUN THE PROJECT
================================================================================

--- Backend ---
  cd backend
  pip install -r ../requirements.txt
  python -m scripts.seed          # seed the database (first time)
  uvicorn app.main:app --reload --port 8000

--- Frontend ---
  cd frontend
  npm install                     # install node_modules (first time)
  npm run dev                     # starts Vite on http://localhost:5173

--- Access ---
  Frontend:  http://localhost:5173
  API Docs:  http://localhost:8000/docs   (Swagger UI, dev only)
  API ReDoc: http://localhost:8000/redoc  (dev only)

9. KEY DESIGN DECISIONS
================================================================================

  1. Single User table for all roles (admin/teacher/student) with nullable
     role-specific columns (class_level, subject_code) — avoids separate tables.

  2. Science engine is pure functions (no DB, no FastAPI) — easy to test and
     extend with new experiment types.

  3. Auto-grading uses percentage-error with linear decay scoring model:
     perfect = 100, at tolerance boundary = 0, clamped at 0.

  4. Experiment.parameters stores expected_values + tolerance in JSON, making
     the grading engine generic across any experiment type.

  5. Submission lifecycle: draft → submitted → graded, enforced at API level.

  6. Frontend uses Vite proxy to avoid CORS issues during development;
     production would use reverse proxy (nginx) or same-origin deployment.

  7. JWT tokens stored in localStorage (simple for demo; production should
     consider httpOnly cookies for better security).
